1436	Удаление обновления — ТОЛЬКО РУЧНАЯ ПРОЦЕДУРА.\r\n1. Сначала точка восстановления и резервная копия.\r\n2. Работающая ОС: Параметры → Центр обновления Windows → Журнал обновлений → «Удалить обновления» (или wusa /uninstall /kb:XXXXXXX).\r\n3. ОС не загружается: WinRE → Дополнительные параметры → «Удалить обновления» (качественное/компонентное).\r\n4. Из WinPE (офлайн): DISM /Image:<том>:\\ /Get-Packages — найдите пакет; DISM /Image:<том>:\\ /Remove-Package /PackageName:<имя>.\r\n   Пакеты servicing stack (SSU) удалять нельзя; удаляйте только LCU/конкретный KB.\r\n5. После удаления приостановите установку обновления (Параметры → Приостановить) и проверьте целостность.\r\n
1437	Recovery — РУЧНОЙ ПОРЯДОК (от менее разрушительного к более разрушительному):\r\n1. Резервное копирование данных (из WinPE скопировать профили на внешний носитель).\r\n2. System Restore (rstrui.exe / WinRE → Восстановление системы).\r\n3. Восстановление запуска (Startup Repair), удаление проблемного обновления/драйвера.\r\n4. DISM /RestoreHealth + sfc /scannow, проверка диска и BCD.\r\n5. «Вернуть компьютер в исходное состояние» (Reset this PC) с сохранением файлов.\r\n6. Восстановление установкой поверх (Repair Install): setup.exe с ISO той же редакции/языка, «Сохранить файлы и приложения».\r\n7. Чистая установка (Clean Install) — последний вариант: диск будет очищен, лицензии/ПО/драйверы подготовьте заранее.\r\nПрограмма ни одного из этих действий автоматически не выполняет.\r\n
1438	Driver Verifier — ТОЛЬКО РУЧНАЯ ПРОЦЕДУРА (программа ничего не запускает).\r\n1. Создайте точку восстановления и резервную копию данных. Убедитесь, что есть доступ к безопасному режиму/WinRE.\r\n2. Включите дампы: Параметры системы → Загрузка и восстановление → «Малый дамп памяти».\r\n3. Запустите verifier.exe от администратора → «Создать нестандартные параметры» → «Выбрать отдельные параметры» (Special pool, Force IRQL checking,\r\n   Pool tracking, Deadlock detection) → «Выбрать имена драйверов из списка» → отметьте ТОЛЬКО подозреваемые сторонние драйверы.\r\n   Никогда не включайте проверку для всех драйверов на рабочей машине.\r\n4. Перезагрузитесь и работайте как обычно до сбоя. Типичный код: DRIVER_VERIFIER_DETECTED_VIOLATION (0xC4) / 0xC9.\r\n5. Разберите дамп кнопкой «Разбор дампов» (модуль в стеке — виновник).\r\n6. ОБЯЗАТЕЛЬНО отключите: verifier /reset, затем перезагрузка. Если система не грузится — безопасный режим → verifier /reset.\r\n
