# Анализ аналогов и концепция WinRepair («швейцарский нож» для ремонта Windows»)

Источники: документация Microsoft (DaRT, Quick Machine Recovery, Secure Boot 2026), описания Tweaking.com Windows Repair, SmartFix, Windows Repair Toolbox,
наборов Hiren's BootCD PE / Medicat / Sergei Strelec, а также практика сервисной работы. Оценки сильных и слабых сторон — мои выводы.

## 1. Что есть на рынке

| Продукт | Сильные стороны | Слабые стороны | Что взять |
|---|---|---|---|
| **Microsoft DaRT** (ERD Commander) | Эталон «офлайн-инструментов»: Locksmith (сброс пароля), Crash Analyzer, Disk Commander, редактор реестра, SFC-сканер, удаление обновлений, проводник, Standalone System Sweeper, Solution Wizard (подсказывает, какой инструмент нужен) | Платный (MDOP/Software Assurance), развитие остановлено на Win10, нет современных вещей (QMR, Secure Boot 2023, NVMe/VMD) | Модель «мастер решений»: симптом → набор проверок → вывод; офлайн-реестр, анализ дампов |
| **Tweaking.com Windows Repair (All-in-One)** | Широкий набор «починок» (сеть, WU, WMI, права, значки, ассоциации), резервное копирование перед правкой, офлайн-режим | Часто «лечит всё подряд» — рискованно; запуск «пакетом» без объяснений; тяжёлый; нет BCD/WinRE | Каталог точечных, обратимых исправлений; бэкап перед правкой |
| **SmartFix (Tweaking/Security)** | Идея «подозрительные автозапуски + сброс сети» одной кнопкой, работает и в WinRE | Узкий набор, эвристика без объяснений | Автопометка подозрительных записей Autoruns |
| **Windows Repair Toolbox** | Портативный «пульт» над десятками чужих утилит, подсказки по задачам | Зависит от скачивания чужих инструментов (нет офлайна), не контролирует результат, нет журнала изменений | Единый интерфейс; но без зависимости от интернета |
| **Hiren's BootCD PE / Medicat / Strelec** | Огромный арсенал, драйверы, сеть, UEFI, образы дисков | Нет логики: «сам выбирай из 300 программ»; нет журналирования действий, отката, единых отчётов; много GUI-программ с разным UX | Мы — «мозг» поверх них: диагностика → рекомендация → безопасное действие |
| **Dism++ / DISM-GUI** | Удобная офлайн-служба образов, очистка WinSxS, драйверы, обновления | Нет BCD/реестра/диагностики | Инъекция драйверов, удаление пакетов — добавить |
| **EasyBCD / BOOTICE / Visual BCD Editor** | Глубокое редактирование BCD/MBR/PBR | Узкие, часто не понимают WinRE-записи | BCD-редактор (уже есть), режимы загрузки, проверка |
| **FRST (Farbar)** | Лучший отчёт по автозапуску/службам для разбора заражений, работает в WinRE | Отчёт — для чтения экспертом; нет действий в 1 клик | Формат «подозрительное» + экспорт |
| **Microsoft WinRE + Quick Machine Recovery (24H2/25H2)** | Автоматический вход в WinRE при сбое, подключение по Ethernet/Wi-Fi, получение исправления из Windows Update | Работает только на Win11 24H2+, исправления «общие» (массовые сбои), не диагностирует конкретный диск | Использовать WinRE как среду; показывать статус QMR; сеть в WinRE |

## 2. Общие слабости всех аналогов (наши возможности)
1. **Нет «мозга»**: кнопки без ответа на вопрос «что с этой машиной?». Побеждает тот, кто сначала диагностирует, потом предлагает действие.
2. **Нет журнала и отката**: сервисный инженер обязан показать, что изменено. У нас: журнал, аудит, копии кустов/BCD/файлов, обратимые «отключения».
3. **Работают с собой (WinPE), а не с целевой ОС** — путаница с буквами дисков, BCD, реестром. У нас целевая ОС выбирается явно.
4. **Тяжёлые и зависимые** от .NET/PowerShell/скачиваний. У нас один статический exe, сеть не обязательна.
5. **Не учитывают новое**: BitLocker/Device Encryption по умолчанию, Intel VMD/RST (диск «не виден»), Secure Boot 2023, WinRE-раздел слишком мал, QMR, Windows 11 24H2.

## 3. Какой должна быть наша утилита
**Принципы:** один exe (< 2 МБ, без зависимостей) · «диагностика → вывод → безопасное действие» · все изменения обратимы и журналируются ·
всегда явная целевая ОС · работает онлайн, в WinPE и в WinRE · данные не уходят в сеть без согласия.

### Архитектура-цель
1. **Ядро** (есть): запуск процессов, журнал, аудит, реестр офлайн, BCD, WinRE, события, SMART.
2. **Каталог действий** (есть: 81 команда + мастер из 17 исправлений) → перевести на **сценарии (playbooks)** в текстовых файлах рядом с exe:
   список шагов с условиями («если BugCheck 0x7B → проверить режим SATA/VMD → предложить инъекцию драйвера»). Новые способы ремонта добавляются без перекомпиляции.
3. **Мастер «Что случилось?»**: симптом (не грузится / BSOD / зависает / вирус / нет сети / не видит диск) → автопроверки → отчёт «найдено» + 1–3 рекомендованных действия.
4. **Отчёт для клиента/журнал работ** (HTML есть) с «до/после», списком изменений и ссылкой на копии для отката.

## 4. Что реализовано в этой версии для WinRE
* Вход в WinRE **при следующей загрузке** и **с немедленной перезагрузкой**: онлайн — `reagentc /boottore`; из WinPE — одноразовая загрузка (`bcdedit /bootsequence`)
  в запись WinRE целевой ОС (ReAgent.xml → BCD). Если записи нет, но `Winre.wim` найден (в т.ч. на скрытом разделе) — запись создаётся автоматически.
* **Windows RE + WinRepair**: копия вашего `winre.wim` + WinRepair.exe, `winpeshl.ini` запускает WinRepair первым, после выхода открывается штатное меню WinRE.
  Оригинальный WinRE и его запись BCD не меняются; создаётся отдельный пункт BCD; удаление — одной кнопкой.
* Определение, что программа запущена внутри WinRE (баннер `[WinRE]`), выход в штатное меню, перезагрузка при закрытии.
* Сохранение журналов/отчётов на диск (ОЗУ-диск WinPE/WinRE очищается при перезагрузке).
* Проверка Secure Boot: есть ли в KEK/db сертификаты 2023 (срок старых — июнь и 19 октября 2026).

## 5. Что советую добавить дальше (по приоритету)
**P1 — самое частое в практике**
1. **BitLocker / Device Encryption** — *реализовано (v1.3)*: заблокированные тома, разблокировка по 48-значному ключу/паролю/.bek (`manage-bde -unlock`), статус, приостановка защиты.
2. **Драйверы хранилища** (Intel VMD/RST, NVMe, RAID) — *реализовано (v1.3)*: Hardware ID устройств без драйвера, поиск INF, `drvload` в WinPE и `DISM /Add-Driver /Image` для офлайн-ОС; частая причина 0x7B/«диск не найден».
3. **Мастер «Что случилось?»** — *реализовано (v1.4)*: 7 симптомов, ~20 проверок, ранжированные находки с действием в один клик. Следующий шаг — вынести правила в playbooks.
4. **Проверка и ремонт раздела WinRE**: свободное место, переезд/расширение раздела восстановления (ошибки обновлений KB5034441-типа), `reagentc /enable` с проверкой.
5. **Playbooks** — *реализовано (v1.5)*: текстовые сценарии `.wrp` (ремонт и свои симптомы), расширяемость без перекомпиляции; см. `docs/PLAYBOOKS.md`.

**P2 — профессиональные возможности**
6. Анализ **Secure Boot / TPM / BIOS-режима** + подсказки по переходу на 2023-сертификаты; пометка носителей, подписанных старым PCA 2011.
7. **Копирование данных до ремонта** (robocopy профилей на внешний диск, проверка SMART до начала работ).
8. **Сеть в WinRE/WinPE**: Wi-Fi-профиль, DHCP/статика, проверка доступа; использование QMR/«Cloud download» там, где доступны.
9. **Офлайн-пользователи**: список, включение/отключение учёток, блокировка; сброс пароля — только с подтверждением владельца (журналируется).
10. **Антивирусная проверка офлайн**: подготовка к запуску Microsoft Defender Offline/Safety Scanner; автозапуск-эвристики (FRST-стиль).

**P3 — удобство и размер**
11. Локализация RU/EN, тёмная тема, режим CLI (`/full`, `/playbook`, `/json`) для автоматизации в мастерских.
12. Локализация RU/EN — *реализовано*. Самопроверка целостности (SHA-256 + проверка подписи) — *реализовано (1.0.0-rc1)*. Подпись exe и сборка ARM64 — *скрипты готовы*, нужен сертификат и проверка на устройстве; размер < 2 МБ — измерить.

## 6. Честные ограничения
* Вход в WinRE из WinPE полагается на корректный `Winre.wim` и BCD; на устройствах с BitLocker WinRE запросит ключ — это штатное поведение.
* Создание «WinRE + WinRepair» требует DISM и драйвер монтирования wim (в Sergei Strelec обычно есть) и ~2× размера winre.wim свободного места.
* Не проверялось на реальном оборудовании в этой сессии — перед внедрением протестируйте на ВМ (UEFI и BIOS), затем на тестовом ПК.
