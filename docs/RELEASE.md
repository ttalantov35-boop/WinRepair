# Процесс выпуска
1. Версия: правьте только `res/version.h` (SemVer: `MAJOR.MINOR.PATCH[-rcN]`; поле `WR_VERSION_RC` — четыре числа для ресурса). Запишите изменения в `CHANGELOG.md`.
2. `./run_tests.sh` (Linux/WSL/MSYS2) — тесты ядра, SHA-256, сценарии, словарь.
3. Статический анализ: `build_msvc_analyze.bat` (из Native Tools) — разберите предупреждения C6xxx/C28xxx.
4. Сборка и пакет — по одному запуску в консоли нужной архитектуры:
   `make_package.bat x64` · `make_package.bat x86` · `make_package.bat arm64` (консоль «ARM64 Native Tools», либо кросс-консоль x64_arm64).
5. Подпись (нужен сертификат подписи кода — OV/EV или облачная подпись): `set SIGN=1`, `set WR_PFX=...` (или `WR_CERT_SHA1=...`), затем `make_package.bat`.
   Скрипт подписывает exe **до** вычисления `MANIFEST.sha256`, поэтому хэши в манифесте соответствуют подписанным файлам.
6. Пройдите `RELEASE_CHECKLIST.md` на реальных/виртуальных машинах.
7. Опубликуйте zip вместе с `MANIFEST.sha256` и значением SHA-256 самого архива (на сайте/в описании выпуска).

## Что даёт самопроверка и чего не даёт
`MANIFEST.sha256` лежит рядом с программой, поэтому злоумышленник с правом записи может подменить и exe, и манифест. Проверка находит **случайное повреждение**
(сбой флешки, неполное копирование) и грубую подмену. От целенаправленной подмены защищает только подпись Authenticode с доверенным сертификатом
и сверка SHA-256 архива с опубликованным значением. В WinPE цепочка доверия часто недоступна — тогда подпись показывается как «не удалось проверить», это не тревога.
